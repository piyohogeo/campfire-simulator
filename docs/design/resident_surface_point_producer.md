# Resident-native surface arrays to Flow Point Emitter

Status: Phase 6CC qualified as a default-off technical phase. The production Sphere Emitter and Resident application activation remain unchanged.

## Boundary

The additive C ABI reads the existing private contiguous arrays owned by `ResidentNativeBackend`; it does not read or synchronize Python `WoodCellState` objects during a tick. Two operations are separated:

- `campfire_native_surface_layout` maps the 24×12×4 cell topology and per-log transform inputs to one persistent contiguous `float32[N,3]` position buffer. Layout is static until log topology or placement changes.
- `campfire_native_surface_channels` scans exposed Resident cells into persistent `float32[N]` fuel, temperature, and smoke buffers. Per-cell temperature uses `clamp((temperature_k - ambient_k) / 500, 0, 2)`. Existing per-log `flow_fuel` and `flow_smoke` values from the committed native publication output are repeated across that log's 360 exposed cells.

The benchmark accesses the Resident backend's private arrays only inside this isolated script. Production does not expose those arrays and does not call the new exports. The C ABI writes directly into preallocated NumPy-owned memory; pointer identity, `float32` dtype, contiguity, and point count are checked after 150 publications. `Vt.*Array.FromNumpy` then creates the explicit owned copy for USD. This is not a claim that USD and the Resident C++ allocation share storage.

## Lifecycle and revision

The fresh Phase 6CB Point stage remains fully authored before Kit connection. After connection the test performs no Prim definition, deletion, relationship, material, layer, or scalar Flow mutation. It writes the existing `pointPositions` once, then only `pointFuels`, `pointTemperatures`, `pointSmokes`, and `campfire:residentRevision` for steady publications, all inside one `Sdf.ChangeBlock`.

Revision is not generated by the surface producer. Every array publication uses the revision of the already-built immutable `ResidentPublishedSnapshot`. The test requires revisions 1 through 150 without gaps, exactly one relevant USD notice per publication, and zero relevant live resync paths. Existing Resident step rollback, session pending/retry, shutdown export, and USD revision-last contracts are not changed or reimplemented here.

## Fixed test condition

- Flow: 110.0.0, unchanged dependency lock
- Hardware: RTX 3090
- Scale: 20 logs × 1,152 cells; 360 exposed cells per log; 7,200 points total
- Emitter layout: one `FlowEmitterPoint`, never one Prim per point
- Measurement: 30 warm-up + 120 measured publications
- Diagnostic thermal state: alternating 0.12/0.30 dry-basis moisture and 760–768 K initial cell temperatures under 150 kW/m²

The hot diagnostic state is chosen to exercise fuel, temperature, smoke, burn, active-block, and viewport paths. It is not a calibrated ignition scenario or a new physical default.

## Result

| Boundary | p95 |
| --- | ---: |
| Static Python/Gf layout, one invocation | 12.0255 ms |
| Static native layout | 0.1469 ms |
| Resident step + immutable snapshot | 2.9702 ms |
| Phase 6CB-style Python/Gf positions + four channel lists | 21.4433 ms |
| Native dynamic fuel/temperature/smoke generation | 0.1395 ms |
| NumPy to owned Vt dynamic arrays | 0.1260 ms |
| USD attribute `Set` | 0.2257 ms |
| `Sdf.ChangeBlock` exit | 0.6946 ms |
| Dynamic USD publication total | 1.0581 ms |
| Kit/Flow/render update | 6.8501 ms |

The old per-frame Python/Gf rebuild divided by native dynamic generation is 153.7× at p95. That ratio includes the deliberate removal of needless position rebuilding: positions now publish once, reducing the steady logical payload from 172,808 to 86,408 bytes and steady updates from five to four. It does not mean the complete simulation frame is 153.7× faster.

All 13 gates passed. Layout and channel maximum absolute errors were zero, buffer pointers remained stable, the Vt copy remained independent after the NumPy source was mutated, all four arrays ended at 7,200 values, revision ended at 150, 150 publications produced 150 notices, and live resync count was zero. Flow reached 845 active blocks; temperature, fuel, burn, smoke, and velocity readbacks were non-empty; the pre-simulation and final RTX captures differed.

The standard regression suite passed 49/49 checks across eight processes in 303.7 s; collapse coverage completed in 180.3 s.

## Decision and remaining work

The native producer removes the Phase 6CB Python object-generation bottleneck and keeps a single Point Emitter as the preferred layout. Production adoption is still deferred because:

- the probe reaches private Resident arrays rather than a session-owned public view;
- static position invalidation for PhysX movement, placement edits, stage replacement, and structural rebuild is not defined;
- per-cell temperature with per-log fuel/smoke replication is a proposed Point mapping, not yet an adopted physical contract;
- session pending/retry must own the Point publication together with the existing immutable snapshot before activation;
- USD remains an owned-copy boundary and Flow/render p95 is independent of the source-generation improvement.

The next default-off boundary should attach a read-only surface view to the `ResidentApplicationSession` owner, specify when layout revisions change, and inject a Point publication failure to prove that snapshot and arrays retry together without advancing the next tick. Production Sphere, physics, JSON schema, dependency versions, defaults, and canonical scenes remain unchanged meanwhile.
