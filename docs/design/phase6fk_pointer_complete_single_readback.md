# Phase 6FK pointer-complete single-readback qualification

Phase 6FJ is frozen as a safe stop. Its nine-operation history is not reclassified because the three C cases did not persist the mandatory NumPy source and converted data pointers. Python identity and `numpy.shares_memory()` are useful evidence, but neither substitutes for positive pointer values proving that the observed source and converted buffers share the same address.

Phase 6FK starts a fresh balanced population. A performs no readback, B performs one public NanoVDB readback and releases all aliases, and C performs one public readback plus exactly one `numpy.asarray(fuel)` before ordered alias release. The fixed order is `ABC / BCA / CAB`, with three representative cases per condition. Only a pre-operation startup prerequisite failure may consume one of two replacement launches; the first pointer, operation, lifecycle, resource, fatal, diagnostic, or cleanup failure stops the population without retry.

For every C case, `fuel_source` and `fuel_array` must contain positive built-in integer pointers read from the public `__array_interface__.data[0]`. The two pointers must be equal, Python identity must be equal, `shares_memory` must be true, shape/dtype/strides/size/nbytes must match, and all weak-reference residuals must be zero after ordered release. Missing, zero, negative, non-integer, or unequal pointers are nonreplaceable operation failures. Raw markers and the final report both preserve the pointers. The adjacent synchronous `numpy.asarray()` Private Bytes delta is bounded to 8 MiB; the fuel logical array is about 39.48 MiB, so this bound distinguishes a zero-copy boundary from a material data copy while allowing small marker/runtime noise.

Absolute limits remain Kit 14 GiB and unique tree 16 GiB, with 512 MiB runner/diagnostic limits and 8 GiB physical/commit floors. Memory waveform metrics remain warning-only. Stage close, extension shutdown, normal OS exit, exact cleanup, and zero fatal/dump/upload are mandatory. Bounded CDB is used only for a native lifecycle failure. Repeated readback, other channel conversion, field persistence, forced GC, private release APIs, production changes, and video are outside this phase.

The machine-readable contract is `scripts/phase6fk_pointer_complete_contract.json`; its adjacent SHA-256 file freezes the exact pre-runtime contract. Phase 6FG and Phase 6FI base contract hashes are also verified before the artifact root is created.

## Formal result

The fresh root completed all nine slots without a startup replacement. A, B, and C each produced three representative startups, complete operation evidence, normal OS exits, and zero cleanup residuals. The C pointers were positive and equal within every process: `3703402725376`, `3977508880384`, and `2704655056896`. Each source and converted object was the same Python `numpy.ndarray`, shared the same public data pointer, and had `uint32[10,349,504]`, stride 4, and 41,398,016 logical bytes. Adjacent `numpy.asarray()` CPU and GPU deltas were 0 in all three C cases, and weak-reference residuals were zero.

The six B/C readbacks added 302,247,936–313,995,264 bytes at the synchronous CPU boundary. The next-frame residual was 268,759,040–280,702,976 bytes; after the finite observation every case was 413,995,008–784,977,920 bytes below its pre-readback value. Adjacent GPU readback deltas were 0 MiB in five cases and 26 MiB in one; every C `numpy.asarray()` GPU delta was 0 MiB. These values describe the public boundary and do not reveal private Flow copy topology.

Kit peak was 14,900,314,112 bytes and unique-tree peak was 15,063,629,824 bytes. The minimum Kit headroom was only 132,071,424 bytes. Stage close completed in 2.538–140.481 seconds (median 5.801 seconds); the 140.481-second B close did not time out or invoke CDB, but remains a significant low-frequency native lifecycle risk under the 180-second bound. Fatal, dump, automatic upload, CDB invocation, and residual counts were zero. The production app SHA-256 remained unchanged.

The formal conclusion is limited to one public readback, one fuel `numpy.asarray()` same-object alias, ordered release, finite observation, and normal shutdown in the fixed four-log fixture. Repeated readback, repeated alias creation/release, other channels, field persistence, and production integration remain unqualified and require a separate frozen phase.
