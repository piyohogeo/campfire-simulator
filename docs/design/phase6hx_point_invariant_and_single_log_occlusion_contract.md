## Canonical production Point-policy source set

The former nonexistent `point_emitter.py` is not replaced by another guessed
single filename. Production `campfire.app` registration, public imports, and
`CampfireAppExtension` composition show that Point policy spans these ordered
roles:

1. `config/extension.toml`: extension registration, dependencies, settings.
2. `app/__init__.py`: public production import/export surface.
3. `app/extension.py`: production composition and scene lifecycle consumer.
4. `resident_native_backend.py`: authoritative native payload/revision source.
5. `resident_snapshot.py`: immutable published field/revision schema.
6. `resident_snapshot_adapter.py`: ordered USD publication/revision checks.
7. `resident_application_session.py`: owner-thread publication transaction.
8. `resident_point_sidecar.py`: Point shape, dtype, identity, order, revision.
9. `resident_point_scene.py`: default-off settings, layout, source, emitter.
10. `resident_point_application_owner.py`: application owner/layout revision.
11. `resident_point_commands.py`: owner-thread command sequence/order.
12. `resident_point_continuity.py`: contiguous group/alignment evidence.
13. `resident_stage_recovery.py`: replacement/revision/recovery ownership.

The versioned manifest records repository-relative paths, roles, deterministic
order, and SHA-256. The shared producer and parent validator reject missing or
non-regular files, the legacy path, duplicate or reordered entries, hash
mismatch, root escape, reparse points, schema/digest mismatch, and different
producer/consumer sets. The 7,287-byte bounded report remains well below its
128 KiB maximum.

The no-Kit preflight must qualify the real producer-to-file-to-bounded-reader-
to-parent path, Phase 6HU atomic fixture, generated-stage fixture, and the
formal parent command in `--prelaunch-only` mode. Its durable
`production_invariant_hash_complete` marker and Kit launch count zero are hard
gates.
